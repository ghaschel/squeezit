# Dependency audit for the QPDF implementation plan

Audited on 2026-10-28 against Squeezit 2.4.3 at `af41b7a`. This audit covers all 55 unique direct npm declarations, all 1,582 lock entries (1,401 versions across 1,194 package names), the complete existing native-tool catalog plus QPDF, 60 Homebrew runtime formula records, Bun, Node, and release Actions.

These are researched upgrade targets and migration requirements. No dependencies were upgraded, and compatibility of a newly resolved graph remains an implementation acceptance gate. The current checkout passed typechecking and 176 fast tests; those are baseline results only. The metadata sweep is exhaustive for the existing lockfile; release-note review focuses on proposed direct/native upgrades and relevant transitive constraints, rather than treating all transitive latest majors as compatible replacements.

## Decisions that affect the plan

- Target Bun **1.4.4**, exact `@types/bun` **1.4.4**, development/standalone Node **24.22.2**, and QPDF **12.4.2** with a verified **11.3.0** compatibility lane. Keep consumer Node `>=22.13.0`.
- **Do not adopt TypeScript 7.0.2:** current typescript-eslint compiler-API support and its `<6.1` peer range exclude it. Try TypeScript **6.0.3** with an explicit development pin and TS5 consumer tests; retain **5.9.3** if that migration fails.
- **Babel 8.0.9 and Astro 7.4.4 need additive compatibility work**, not just new version strings. Preserve existing Babel7/Astro5 support; fallback patches are **7.29.7** and **5.18.2**. The old Astro branch may retain advisories, which must remain visible if held.
- **Do not force transitive majors outside parent ranges.** Latest Grunt still owns Glob7/inflight/osenv; ATTW intentionally owns a TypeScript prerelease compiler. Modern Oclif/Execa also retain particular EJS, wsl-utils, and pretty-ms major lines.
- **Hold ExifTool 13.60 development and unreleased Gifsicle 1.99.** Targets are ExifTool **13.55 production** and Gifsicle **1.98**. Keep embedded Node on 24 while testing Node26 separately; its Intel macOS support tier differs.
- **Do not raise every native minimum to Homebrew's newest version.** Several Debian packages already fail existing floors or are unavailable. Repair provider guidance and validate a source/manual path where needed. libheif **1.23.7** is a security-priority target; distribution backport status needs explicit verification.
- Registry advisory matching found **136 distinct advisory URLs across 30 packages / 36 locked versions**. These are version-range matches, not proven application exploits. The final resolved graph needs a new audit; unchanged findings must be reported, not suppressed.

ESLint10.0.3 satisfies @eslint/js10.0.1 (^10), simple-import-sort12.1.1 (>=5), unused-imports4.4.1 (^8/^9/^10), and typescript-eslint8.57.1 (^8.57/^9/^10). Latest runtime direct packages all declare engine support that includes Node22.13. New transitive resolution must still be audited after installing. Latest Babel8 (^22.18 || >=24.11), Astro7.4.4 (>=22.23.4), tsup9 (^22.18 || ^24.11 || >=26), lint-staged17 (>=22.22.1) require a newer development runtime. ### Definite holds and migration branches

- **TypeScript7.0.2 is a definite incompatible replacement for this toolchain today.** Latest typescript-eslint requires <6.1 and upstream confirms its need for the legacy compiler API. TS7 root exports are a version shim, not the old compiler API. TS6.0.3 is the newest compatible candidate; add explicit types (e.g. node/bun) because TS6 defaults types to an empty list, and verify DTS output under supported TS5 consumers. Retain5.9.3 if this bounded migration fails. Do not force TS7 through overrides or ignore peer failures. Sources: [registry](https://registry.npmjs.org/typescript-eslint/latest), [upstream issue](https://github.com/typescript-eslint/typescript-eslint/issues/12518), [Microsoft TS7](https://devblogs.microsoft.com/typescript/announcing-typescript-7-0/), [TS6 changes](https://www.typescriptlang.org/docs/handbook/release-notes/typescript-6-0.html).
- **Babel8 needs adapter work**: current source api.assertVersion(7) is an actual rejection, not merely an untested concern. A small dual-version implementation and Babel7/8 package-consumer tests may permit8.0.9. If not,7.29.7 is the latest7 patch, but document it as a hold. [Migration](https://babeljs.io/docs/v8-migration/).
- **Astro7 needs additive host support**, not a blanket replacement of peer^5.18.0. Astro6 changes Vite environment setup and Astro7 uses Vite8/Rolldown. Existing adapter injects the Vite plugin through astro:config:setup. Test static client assets, generated references and one-run behavior in5/6/7; remain5.18.2 if new majors cannot be made compatible. Astro6 latest6.4.8. Holding old Astro may retain advisories; report that honestly rather than calling it safe. [v6](https://docs.astro.build/en/guides/upgrade-to/v6/), [v7](https://docs.astro.build/en/guides/upgrade-to/v7/).
- **Transitive historical majors are not independent direct upgrades.** Grunt1.6.3 still requires glob~7.1.6. glob7/inflight and osenv remain upstream-owned legacy dependencies; inflight1.0.6 and osenv0.1.5 are themselves latest and deprecated. Replacing them with unrelated modern majors violates parent constraints. The attw compiler version is package-owned, also not a reason to override all TypeScript copies. Audit actual resulting graph; document retained packages with owner/range/reason.

### Bun

Bun official stable is **1.4.4**, released October22,2026. package.json and four workflow entries pin1.3.5; actual preflight runtime was1.3.14. Change pins together and @types/bun to1.4.4. [Official1.4.4](https://bun.sh/blog/bun-v1.4.4), [1.4 behavior changes](https://bun.sh/blog/bun-v1.4).

Relevant changes since1.3.5 include a runtime rewrite and Node26 compatibility in1.4, native addon ABI147, changed paused readable.read() behavior, strict TOML, no automatic .env loading when invoked as node, and isolated-linker default for new monorepos. Existing lockfiles keep hoisted behavior. Existing configVersion1 and undeclared transitive imports make clean frozen-install/build tests necessary; explicitly retain linker behavior if needed. Do not replace project typecheck with new bun check: that is a separate toolchain choice and does not solve TS compiler-API compatibility.

Keep `DEPENDENCY_CATALOG.minimumVersion` as the compatibility gate. Record audited target versions separately in a checked-in `scripts/native-tool-targets.json` (version, source URL, SHA-256, verified date, platform, rationale). ### Compatibility and platform findings

- QPDF min11.3.0 aligns with [Debian bookworm11.3.0-1+deb12u1](https://packages.debian.org/bookworm/qpdf); [trixie12.2.0](https://packages.debian.org/trixie/qpdf) also satisfies it. - QPDF12.4.2 is Apache2.0. It has a parsing behavior change rejecting trailing junk in bounded numeric CLI options; always pass canonical6/9. QPDF12.3+ needs C++20 to build; upstream Linux binaries use Ubuntu22.04 baseline. macOS upstream binaries are unsigned/unnotarized; prefer Homebrew. [Release notes](https://qpdf.readthedocs.io/en/stable/release-notes.html).
- QPDF's `--is-encrypted` uses0=encrypted and2=not-encrypted, unlike normal exit codes. Inspection/parsing errors must not be mistaken for safe input; the separate structural/JSON inspection must fail closed. Normal operations use0 success,3 warning,2 error. A no-warning parse/check policy avoids committing silently repaired PDFs. Object generation and generalized Flate compression are appropriate; do not use `--optimize-images`, `--jpeg-quality`, decryption, or signature-removal switches for the requested lossless contract. [CLI](https://qpdf.readthedocs.io/en/stable/cli.html).
- Oxipng10.2 changes optimization presets and reductions, so output bytes/sizes can change. Existing `-o`, `--strip all`, and `--out` calls remain within documented CLI; Rust minimum rises to1.88. [Changelog](https://raw.githubusercontent.com/oxipng/oxipng/v10.2.1/CHANGELOG.md).
- Gifsicle1.98 introduces a16384x16384 default logical-screen bound, changes invalid-input handling, and fixes memory-safety issues.
